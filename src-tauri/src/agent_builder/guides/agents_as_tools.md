- The user's own agents can be used as steps. Each one is a tool of the provider `agents` whose tool name is the agent's id; its arguments are that agent's start inputs and its result is that agent's outputs. Only use agent ids the request gives you; never invent one.
- To run another agent as one step, use a `tool` node with `provider_id: agents`, `tool_name: <agent id>`, a `title` such as "Run Lead qualifier", `timeout_ms: 600000`, and one `tool_parameters` entry per input of that agent (`{ type: variable, value: [step, output] }` for values from earlier steps, `{ type: constant, value: ... }` for fixed ones). Later steps read its outputs as `{{#<step id>.json.<output>#}}`; `{{#<step id>.text#}}` holds its single text output, or all outputs as JSON.
- For a team, use one `agent` node as the coordinator: its `instruction` says what each member is for, and its `tools` list holds `agents/<agent id>` for every member agent. Keep the other tools in that list when adding a member.
- An agent used as a step or team member cannot stop to ask the user yet, so do not wrap these calls in `human-input` inside the called agent; put any approval in the calling agent, before the step that sends or spends.
- An agent never calls itself, and calls go at most three agents deep.
